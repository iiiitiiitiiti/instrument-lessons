# 009. Web フォントを使わない

- 日付: 2026-09-10
- 対象: `src/styles.css` の `--font-sans` / `--font-mono`

## 背景

視覚設計で最も効くのは書体である。見出しに明朝を当てれば「教本」の顔になり、
デザイン性は一段上がる。日本語の Web フォントを使うかどうかを決める必要があった。

一方このサイトは PWA で、練習中にオフラインで開くことを前提にしている（DDR 003・PWA 対応）。
音は合成しているため音源の取得が要らず、本文はバンドル内にあり、完全にオフラインで動く。

## 決定

**システムフォントだけで組む。** 見出しも本文もデバイス標準の日本語フォント
（`system-ui` → Hiragino Sans → Noto Sans JP）に任せ、書体では個性を出さない。
代わりに文字サイズ・行間・字送り・余白・罫で階層を作る。

等幅（`ui-monospace` 以下、いずれも端末内蔵）は**数字にだけ**使う。
レッスン番号・件数・日数・指番号のように、桁が揃うことに意味がある箇所に限る。

## 比較した代替案

- 却下: **Google Fonts で Zen Old Mincho などを読む** — 見た目は最も良くなる。だが
  Service Worker の precache 対象は `globPatterns` に挙げたローカルの生成物だけで、
  外部ドメインのフォントは入らない。オフラインで開いたときに書体が落ちて、
  行間・字送りを書体前提で詰めた分だけ崩れる。オフラインで確実に動くことを優先した
- 却下: **日本語フォントを自ホストしてバンドルに入れる** — オフラインでも崩れない。
  しかし日本語のサブセットなしのフォントは数MB規模で、
  現在のビルド（322 KiB）を10倍以上に膨らませる。練習のたびに開くアプリとして釣り合わない
- 却下: **サブセット化した日本語フォントを同梱する** — 容量は抑えられる。ただし本文が
  MDX で今後増え続ける（プランBで Lesson 03–15）ため、使う字が確定しない。
  サブセットの作り直しをビルド手順に抱えることになる
- 採用: **システムフォントのみ。等幅は数字だけに使う**

## 影響範囲

- 全画面の見た目。Windows・Mac・iOS で見出しの字面が変わる（それぞれの標準書体になる）
- プランBで本文が増えても、フォント関連の作業は発生しない
- 等幅スタックには日本語グリフが無いため、等幅指定の中に日本語を混ぜると
  その部分だけ別の書体に落ちる。等幅は数字と英字に限るのはこのためでもある

## 検証

実ブラウザ（Mac・幅 320／390px）で本文と見出しの字面・行間を目視で確認した。
ビルド後の資産は CSS 13.98 KiB・JS 280 KiB で、フォントの追加取得はない。

判断が間違いだったとわかるのは、端末標準の書体差で見出しの印象が破綻したとき。
その場合は、見出しだけをサブセット化した1書体で自ホストする案に戻る。
