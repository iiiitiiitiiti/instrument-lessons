# 014. 楽譜ライブラリは権利の検証記録を型で必須にし、テストでビルドを落とす

- 日付: 2026-09-11
- 対象: `src/instruments/ukulele/songs/`、`tests/ukulele/songs.test.ts`、
  `docs/songs-licensing.md`、`src/routes.tsx`、仕様 §5・§6

## 背景

`/ukulele/songs` に掲載できるのは、日本と米国の両方で保護期間が満了した曲だけ（DDR 004）。
判定は作者の没年と出版年で決まるが、**どちらも人が調べて書き込む値**で、間違いや書き漏らしが
そのまま公開面へ出る。仕様 §6 は「権利情報のビルド時強制」を求めていた。

実際に裏取りを始めてすぐ、仕様自身の記述に穴が見つかった。仕様の課題曲表は Kaimana Hila を
「Charles E. King（Andrew Cummings 補作）」としていたが、**この補作者は没年を追えない**。
1人でも追えなければ日本側の判定は確定しない。

## 決定

### 1. 権利の検証記録を型で必須にし、テストで検査する

`SongLicensing` を必須フィールドにし、`tests/ukulele/songs.test.ts` で18項目を検査する。
検査するのは、作者全員の没年、出版年の範囲、出典の scheme、検証日、
`docs/songs-licensing.md` の記録など。揃わないとビルドが落ちる。

**テストが見られるのは記録の「存在」と「形」だけで、没年や出版年の「正しさ」は見られない。**
正しさは裏取りの手順で担保する。この限界はテスト本体のコメントにも書いた。

### 2. 作者は配列で持つ

`lyricist` / `composer` の1人ずつではなく `authors: SongAuthor[]`。共作曲と補作者を
1人に丸めると、追えない作者の存在が記録から消える。仕様 §6 の型もこれに合わせて改訂した。

### 3. `firstPublished` を `earliestPublication` へ改める

確認できた出版が最古とは限らない。「初出版」と名乗ると、裏取りしていないことを断定してしまう。
米国側の判定（1929年より前）には**確認できた年**で足りる。

### 4. 出版年が特定できない伝承曲は `"traditional"` + `usBasis`

聖者の行進は単一の初出版を特定できない。年を無理に1つ書かせるのではなく、
米国側の根拠を文章で書かせる。

### 5. 曲データは `src/` 側へ置き、1曲1ファイルにする

仕様 §5 は `content/ukulele/songs/*.ts` としていたが、`content/` は MDX 本文の置き場。
曲データは型検査とテストの対象になる値なので、`chords.ts` や `curriculum.ts` の隣に置く。
1曲1ファイルは、曲を1つずつコミットで足すため。

### 6. ライブラリの画面は楽器側が持つ

`Instrument` に `songLibrary?: { ListPage, DetailPage }` を足した。曲はコード・進行・譜面を
持つため、弦やコードを持たない楽器（オタマトーン）と共通化できない（DDR 001）。
`mdxComponents` が既に楽器固有のコンポーネントを契約に載せているので、同じ扱いに揃えた。

### 7. 進行は原譜を出典に、割り振りは教材が決める

Web のコード譜サイトの譜は他人の編曲で、写すとそれ自体が問題になる。原譜から初心者キーへ
移して小節へ割り振る作業は編曲そのものなので、Lesson 08 と同じく「この教材の進行」と明記する。

## 比較した代替案

- 却下: **権利を実行時に検査して画面へ警告を出す** — 公開されてからでは遅い。
  ビルドを落とせば、間違ったデータが公開面に出ない
- 却下: **曲数（15曲）を目標として守る** — 判定を曲数の都合で緩めると DDR 004 が無意味になる。
  仕様の「15曲」は候補の目標値であって合格ラインではない、と仕様側へ書き足した
- 却下: **曲データを MDX にする** — レッスン本文と同じ流儀に見える。しかし曲は構造化データで、
  絞り込みのために機械が読む。MDX では型検査とテストが効かない
- 却下: **`SongRef.chords`（`curriculum.ts` 側）を廃止して曲データから引く** — 二重管理は消える。
  しかし `curriculum.ts` は core の型だけで完結しており、曲データへ依存させると
  レッスン一覧の描画が曲データの読み込みを待つ。**一致をテストで担保するほうが軽い**
- 却下: **曲を持たない楽器の `/songs` に「まだありません」を出す** — プランではそう決めていた。
  だが登録楽器が1つの現状では到達しない分岐で、テストも書けない。NotFound へ倒した
- 却下: **`chords` を任意にする** — 進行や譜面と揃う。しかしコードが無い曲は
  「今の自分が弾ける曲」の絞り込みに乗らず、ウクレレの楽譜ライブラリとして役に立たない
- 採用: **型で必須にし、テストで検査し、記録を `docs/songs-licensing.md` と対で維持する**

## 影響範囲

- 曲を足すときは `docs/songs-licensing.md` への追記が必須。忘れるとテストが落ちる
- MDX プラグインの `include` を `.mdx` に限った。既定では `.md` も MDX として扱われ、
  テストが `docs/songs-licensing.md` を `?raw` で読めない
- ルートを2本足した（`/:instrumentSlug/songs` と `/:instrumentSlug/songs/:songId`）。
  静的セグメントが動的セグメントより優先されるので `:lessonSlug` より先に当たる

## 未達（このプランで終わっていないこと）

- **Aloha ʻOe と Kaimana Hila の進行は載せていない。** 原譜は入手できたが、
  スキャンされた楽譜から小節ごとの和声を書き起こす作業はこちらで検証できない。
  理由と次の一手は `docs/songs-licensing.md` の「譜面の状況」に書いた
- **ハワイアン曲の追加も未着手。** 権利の裏取りは進むが、曲ごとに
  初心者キーのコードを決める必要があり、そこが検証できない

## 検証

- 206 tests / lint / build 通過。権利の18項目は**わざと違反データを入れて落ちることを確認**した
  （没年・出版年・出典の scheme・未来日・コード名順・進行と譜面の集合一致・課題曲の整合・記録漏れ）
- 実ブラウザ（dist を preview）で 320px を実測。横スクロールなし。絞り込み3つが期待どおり動く
  （弾ける曲だけ → 聖者の行進のみ、4コード → Aloha ʻOe、5コード以上 → Kaimana Hila、
  組み合わせで0件のときは案内が出る）。タップ領域は44px 以上
- 曲ページで、コード図・歌詞コード譜・進行の表・掲載の根拠（畳んだ状態）が出ることを確認

判断が間違いだったとわかるのは、テストが通ったまま保護期間中の曲を載せてしまったとき。
その場合、機械検査では足りないという結論になるので、掲載前に人が確認する手順を足す。
