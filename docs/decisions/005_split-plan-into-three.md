# 005. 実装プランを3本へ分割する

- 日付: 2026-09-10
- 対象: `docs/superpowers/plans/`

## 背景

仕様には、レッスン15本・練習ツール7種・楽譜ライブラリ15曲・進捗記録・デプロイが含まれる。これを1本のプランへ書き下ろすと数千行になり、実装の途中で判明する事実を反映できない。

## 決定

3本へ分ける。それぞれが単独で動くソフトウェアを作る形にする。

- **プランA（基盤）** — 環境構築・音声エンジン・コード図・レッスン基盤・進捗・デプロイ・PWA + Lesson 01-02。完了時点で「公開された、2レッスン分動くサイト」が残る
- **プランB（ツールと本文）** — 練習ツール5種 + Lesson 03-15 + 課題曲3曲
- **プランC（楽譜ライブラリ）** — 曲データ型・権利検証・一覧ページ・ハワイアン12曲

B と C はプランAの完了後に書き起こす。

## 比較した代替案

- 却下: **1本のプランへまとめる** — 全体像は一度に見える。ただし着手前の机上の想定で数千行を書くことになり、Aの実装で判明する事実を反映できない
- 却下: **レッスン単位で細かく分ける** — 各プランが小さくなりすぎ、単独では動くものが残らない
- 採用: **3本へ分割し、Aから順に書く**

## 影響範囲

- 進め方全体。プランAの完了が、B と C の執筆の前提になる
- 各プランのレビュー（規律8）は個別に通す

## 検証

プランAのレビューで、机上で書いた箇所に実際に動かない指摘が3件出た（ルート定義・テストのクリーンアップ・ビルド検査テスト）。全体を一度に書いていれば、同種の誤りが3倍の分量で埋もれていた。

**判断が間違いだったとわかる条件:** プランAの完了後、B と C の内容がAの実装から何も影響を受けなかったとき。その場合は分割が過剰だった。
