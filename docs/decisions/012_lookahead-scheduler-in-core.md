# 012. 拍を刻む仕組みを先読みスケジューラで作り、core に置く

- 日付: 2026-09-11
- 対象: `src/core/audio/output/scheduler.ts`、`src/core/widgets/Metronome.tsx`、`src/core/widgets/TempoControl.tsx`

## 背景

Lesson 04 以降の12レッスンが「メトロノームに合わせて」を前提に書かれているのに、
その道具が無かった。仕様 §8 は Metronome を core に置き、「Web Audio のスケジューラで
正確に刻む」と定めている。

刻む仕組みは、あとから StrumPattern（ストロークの再生）と SongSheet（伴奏の再生）でも要る。
最初にどこへ置くかで、その2つの作りが決まる。

## 決定

**先読みスケジューラを `core/audio/output/scheduler.ts` に作り、Metronome と
TempoControl も core に置く。**

予約（音）と通知（画面）を別の時計で動かす。

- 音は `AudioContext` の時間軸で、25ミリ秒ごとに 0.25 秒先までまとめて予約する
- 画面は `requestAnimationFrame` で、音が鳴る時刻に合わせて更新する
- 拍の列挙は `planBeats` として純関数に切り出す
- 遅れの追いつきは `catchUpCursor` として純関数に切り出す

## 比較した代替案

- 却下: **`setInterval` の中で直接鳴らす** — 実装は最短。だがタイマーの揺れが
  そのまま音の揺れになる。メトロノームは揺れたら道具として無意味
- 却下: **`AudioWorklet` で刻む** — 最も正確。しかし仕様 §9 が「AudioWorklet より単純で
  ブラウザ差の影響を受けにくい」方針を既に採っており、合成側と流儀が食い違う
- 却下: **拍を全部先に予約する（曲の長さぶん一括）** — スケジューラが要らなくなる。
  だが演奏中のテンポ変更ができず、停止しても予約済みの音が鳴り続ける
- 却下: **予約した時点で画面を更新する** — rAF が不要になる。だが 0.25 秒先の分を
  予約するので、表示が音より最大 0.25 秒先に動く
- 却下: **Metronome をウクレレ側に置く** — 今は使う場所がウクレレのレッスンだけ。
  ただし拍を刻むことは楽器に依存せず、オタマトーンでもそのまま要る（DDR 001 の趣旨）
- 採用: **先読みスケジューラ＋純関数の切り出し、core へ配置**

## 影響範囲

- StrumPattern はこのスケジューラを使っている。SongSheet の伴奏再生も同じ形になる
- テンポの値はスケジューラへ直接渡さず ref 経由で読む決まりにした。演奏中に
  テンポを変えてもスケジューラを作り直さずに済み、拍が途切れない。
  **この流儀を外すと「鳴っているのに止まる」不具合が出る**（StrumPattern で実際に踏んだ。
  MDX のインライン配列が依存に入っていて毎レンダーで作り直されていた）
- `cycle`（拍子やパターン1周の長さ）を渡さないと、裏タブから戻ったときに
  1拍目のアクセントや空振りの位置がずれる

## 検証

- `tests/core/scheduler.test.ts` 26件。窓の切り出し・連続性・テンポ変更・
  間隔 0／負／NaN の歯止め・追いつき・小節の頭からの再開・二重開始
- `now` を注入できるようにして、偽タイマーで start／stop／追いつきを検証した。
  **追いつき処理を外すとテストが落ちることを実測で確認**（恒真テストにしないため）
- 実ブラウザ: BPM 60 で拍の間隔が 1.000000 秒（揺れなし）、演奏中に 60→120 へ変えると
  1 秒から 0.5 秒へ途切れず切り替わる、停止で予約が止まる、レッスンを離れると止まる

判断が間違いだったとわかるのは、裏タブの絞り込みが 0.25 秒の先読みでも足りず、
戻るまで音が飛ぶ形になったとき。その場合は先読みを伸ばすか、
`visibilitychange` で止めて復帰時に鳴らし直す。
