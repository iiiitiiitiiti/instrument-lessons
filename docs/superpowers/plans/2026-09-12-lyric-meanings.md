# 歌詞の意味（日本語）を各曲に付ける

- 日付: 2026-09-12
- 依頼: 「英語わからんよ」（ユーザー）。歌詞の意味が分からないまま練習している状態を解消する

## 要件

- 何を作るか — 掲載中の6曲に日本語の意味を付け、歌詞コード譜の下に出す
- 誰が使うか — ハワイ語と英語のどちらも読めない独習者（ユーザー本人）
- 成功条件 — 譜面の各行に対応する日本語が読め、どの行が何を歌っているか分かる

## 何をどう訳すか

- **ハワイ語の5曲は、原詞（ハワイ語）から訳す。** 語ごとの意味は辞書（Pukui-Elbert、wehewehe.org）で引き、
  引いた語釈を曲データのコメントに残す
- **1923年版に印刷されている英語詞は、意味の照合にだけ使う。** 歌うための意訳で、原詞と行が対応しない
  （Kaimana Hila では英語詞に合わせて音符が足されている。`kaimana-hila.ts` のコメントに記録済み）。
  英語詞の全文はリポジトリに書かず、ページ番号だけ残す。**訳の元にしない**
- **huapala.org の英訳は意味の確認だけに使い、表現は写さない。** 訳者の権利がある（DDR 014 と同じ理由）
- 聖者の行進は、載せている英語詞をそのまま訳す
- Kuʻu Pua i Paoakalani のように歌詞へ英語が混ざる曲は、混ざったまま意味が通るように訳す
- **意訳は行の中だけ。行を跨いで語を動かさない**（1行ずつ並べる形が壊れるため）
- 地名・花の名は、読み方をカタカナで添え、短い説明を許す
  （「モク・オ・ケアヴェ（ハワイ島の雅称）」「リーリーレフア（パーロロに降る雨の名）」など）

## 設計

- `Song` に `meaning?: { line: string; meaning: string }[]` を足す。`line` は歌詞コード譜の歌詞行そのもの
  （コードを外して塊の文字を連ねたもの）。**行数の一致だけでなく、`line` が歌詞と一致することをテストで検査する**。
  添字だけの対応にすると、行を足したときに一致したままずれる
- 空行（節の区切り）は持たない。表示側が歌詞の行を順に見て、空でない行ごとに添字を進める
- 表示は**歌詞の各行のすぐ下に意味を置く**。行の中の塊組み（DDR 013）は `inline-flex` の話なので、
  行の後ろに別の要素を置いても折り返しは変わらない。歌詞を二重に出さないので、画面も短い
- 意味の要素には `.songsheet__text` を使わない（既存のテストが歌詞の文字を数えているため）
- 曲ページとレッスンの譜面の両方に出す（`LibrarySongSheet` にも渡す）

### 比較した案

| 案 | 利点 | 欠点 |
|---|---|---|
| A. 譜面の下に行ごとの意味を並べる | 譜面と意味を分けて読める | 歌詞を二重に出すので画面が長い。行の対応を目で追う手間が残る |
| **B. 歌詞の各行の下に意味を挟み込む（採用）** | 対応が最も分かりやすく、画面も短い | 再生中に光る行の間隔が広がる |
| C. `<details>` で畳む | 譜面が短く保てる | 開かないと読めない。今回の依頼は「意味が分からない」なので既定で見せたい |
| D. 別ページにまとめる | 譜面が汚れない | 練習中に行き来することになる |

## テスト

- `meaning` を持つ曲は、行数が歌詞コード譜の歌詞行数（空行を除く）と一致する
- `meaning[i].line` が、パーサで読んだ i 行目の歌詞と一致する
- 各行の意味が空でない
- 歌詞コード譜を持つ曲はすべて `meaning` を持つ（6曲そろってから有効にする）
- `SongSheet`: `meaning` を渡すと各行の下に意味が出て、**2行目の意味が2行目の直後にある**。渡さなければ出ない

## ステップ

1. 型・`SongSheet`・`LibrarySongSheet`・曲ページと、行数のテスト → `npm test`
2. 6曲の訳を1曲ずつ入れる（1曲＝1コミット）。辞書で引いた語釈と、照合に使った原譜のページをコメントへ残す → 曲ごとに `npm test`
3. 全曲がそろったら必須のテストを有効化し、`docs/songs-licensing.md` に意味の出どころを書く → DDR 020
4. 公開して、幅 320px の実ブラウザで曲ページとレッスンを確認する

## 確認できていないこと（ユーザーが寝ている場合の仮定）

- **意味は既定で表示する**（畳まない）。外れた場合の影響: 譜面の下が長くなる。畳む形へ変えるのは小さな変更
- **歌える日本語（歌詞として歌える訳）にはしない。** 意味が分かることを優先する


## プランレビュー

- レビュアー: fable-advisor（Claude Fable、作成者の Opus とは別モデル）
- 結論の要旨: 骨格は妥当。ただし前提1つ（英語詞の権利）と却下理由1つ（表示案B）が誤り

### 反映した指摘

1. **最大のリスク: 1923年の英語詞を訳の元にすること。** 歌うための意訳で原詞と行が対応せず、
   「どの行が何を歌っているか分かる」という成功条件を満たせない。**原詞から訳し、英語詞は照合用に降格した**
2. **権利の前提が誤り。** 日本側の判定は「作者全員の没年」（DDR 004）で、「1923年出版」では根拠にならない。
   英語詞の作者は曲データの作者一覧に居ない。英語詞を引用しない形に変え、全文はリポジトリへ書かないことにした
3. **表示案Bの却下理由が誤り。** DDR 013 の塊組みは行の中の `inline-flex` の話で、行の後ろに要素を置いても
   折り返しは変わらない。Bの方が画面も短い。**採用をBへ変え、Aの欠点を書き直した**
4. **データの形。** 添字だけの対応では、行を足したときに一致したままずれる。`{ line, meaning }` の対にして、
   `line` が歌詞と一致することを検査する
5. **意訳の範囲。** 「逐語訳にしない」だけでは行を跨ぐ意訳を許してしまう。「行の中だけ」と制約を書いた
6. 意味の要素に `.songsheet__text` を使わない（既存テストの二重カウント）。対応の順序もテストする
7. 固有名詞はカタカナだけでは足りない（モク・オ・ケアヴェ、リーリーレフア）。短い説明を許すことにした

### 見送った指摘

- **必須化のテストを有効にするまで push しない** — 規律11（検証が済んだら公開まで自動で進める）と噛み合わない。
  必須のテストは最後に足すが、途中の曲も1曲ずつ公開する。訳が無い曲は今と同じ見た目で、壊れるところが無い
