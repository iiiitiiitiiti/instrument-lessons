# 楽譜ライブラリ: お手本の再生 実装プラン

- 日付: 2026-09-11
- 依頼: 「曲なんだけど、実際に弾いてるところを聞けるようにできない？ 正解を聞きたい」

## 要件

- 何を作るか — 歌詞コード譜に「お手本の再生」を付ける。ウクレレのストローク伴奏とメロディを原譜どおりの拍で鳴らす。テンポは変えられ、メロディは消せる
- 誰が使うか — ウクレレを始めたばかりの独習者。主にスマートフォンで使う
- 成功条件 — 掲載中の6曲すべてで、譜面の範囲（1番・サビ）がメロディとコードの両方で鳴る。再生中に光るコードは、譜面上の位置と一致する

### ユーザーが決めたこと

- 鳴らす音は、伴奏＋メロディ。メロディはボタンで消せる
- 付ける場所は、曲ページと Lesson 08・11・14 の課題曲の譜面の両方。Lesson 08 は曲データから譜面を出す形に揃える

### 仕様 §8 との関係

仕様 §8 では「SongSheet の全体をテンポ可変で伴奏再生」を外した。理由は、歌詞コード譜の記法がコードの替わる場所しか持たず、各コードの長さを書けないためだった。

今回も**記法は変えない**。Lesson 12 が教える規則は「角かっこの直後の文字でコードを替える」の1つのままにする。拍の長さとメロディは、曲データの別フィールドに持つ。

## 設計

### データの形: ABC 記法の小さなサブセット

| 案 | 利点 | 欠点 | 撤退コスト |
|---|---|---|---|
| **A. ABC 記法のサブセットを曲データに書き、自作パーサで読む（採用）** | 標準の記法で、第三者も読める。abcjs で五線譜に描いて原譜と見比べ、転記を確かめられる | パーサを自作する | パーサ1ファイルとテスト |
| B. TS のイベント配列を直接書く（`{ note: "G4", len: 4 }` の並び） | パーサが要らない | 長くて読みにくい。五線譜に描けないので、転記ミスを原譜と見比べる手段が無い | 小 |
| C. abcjs を依存に入れ、再生も任せる | 実装が最も速い | 音源（soundfont）を外部から取るため、オフライン（PWA）で鳴らない。既存の撥弦音と音色が揃わない。バンドルが約400KB増える | 依存の削除と置き換え |

A を採る。転記の正しさを確かめる手段を持てるのは A だけになる。

abcjs は検証用に scratchpad の HTML で CDN から読むだけにし、リポジトリの依存には入れない。

#### サブセットの範囲

- ヘッダ: `M:4/4`（分母は4だけ）、`L:1/16`、`K:C`（C だけ。原譜のキーは C へ移して書く）
- 音符: `^` `_` `=` の臨時記号、`A-G` `a-g`、`,` と `'` のオクターブ、長さの数字。**臨時記号は ABC の標準どおり小節の終わりまで続く**
- 休符 `z`、タイ `-`、小節線 `|` `||` `|]`、コード記号 `"C7"`、途中の拍子変更 `[M:2/4]`、`%` のコメント
- 歌詞 `w:`: 音節は空白か `-` で区切る。`_` は前の音節を次の音符へ伸ばす（メリスマ）。休符は音節を取らない。**タイで続く音符も枠を1つ使うので、`_` を書く**（abcjs の描画で確かめた規則。書き忘れはパーサがエラーにする）
- 歌詞は歌詞コード譜と同じ綴り（ʻ・長音符号を含む）で書く
- 16分音符の格子に乗らない長さ（32分音符・3連符）はエラーにする。必要な曲が出たら、その時点で格子を見直す

### 再生

- **既存の `createScheduler` をそのまま使う。** 1ステップを16分音符1つにする。BPM 160 でも1ステップ 0.094秒で、スケジューラの下限（0.05秒）を割らない
- 事前に「ステップ番号 → そのステップで鳴らすもの（ストローク・メロディの音・コードの切り替え）」の表を作る。スケジューラは表を引くだけにする
- ストロークは曲データで1つに決める。聖者の行進はダウンだけ（Lesson 08）、ほかは D-DU-UDU。鳴らし方は StrumPattern と同じ（アップは高い2本を弱く）。画面での切り替えは付けない（レビューで削除。下記）
- メロディの音は `core/audio/output/voice.ts` を新設して作る。三角波に立ち上がりと減衰を付けた音で、撥弦音の伴奏と聞き分けられるようにする
- **2/4 の曲**（Pālolo、Kaimana Hila）は、音価を2倍にして 4/4 で書く。D-DU-UDU は4拍で1周する形なので、原譜の1小節に1周が収まる。聞こえる音は、BPM を倍にした 2/4 と同じ
- **フェルマータと rit.** は無視し、テンポどおりに鳴らす。該当する曲では、再生の操作の下に一言出す（`performance.note`）
- 弱起は、最初の小節を短く書く。弱起の小節ではストロークを鳴らさず、メロディだけを出す。ストロークは小節の頭を基準に数える
- 表示する BPM は、2/4 の曲では倍書きした後の4分音符の速さになる
- 最後の音の時刻で止め、ボタンの表示を戻す（スケジューラには終わりの概念が無いので、表を引く側が止める）。繰り返し再生はしない
- タブが裏に回ったら止める。弱起や 2/8 の小節があると、スケジューラの追いつき処理（周期の倍数へ切り上げ）で小節の途中から再開してしまうため

### 表示

- `SongSheet` に `performance?` を足す。渡されたときだけ、譜面の上に「再生／止める」「テンポ」「メロディ」「ストローク」の操作を出す
- 再生中は、今鳴っているコードの**塊**を光らせる（名前ではなく位置で引く。同じ C が譜面に何度出ても、光るのは1か所）。譜面の下の図も今のコードに合わせる
- `performance` を渡さない使い方（Lesson 12 の記法の例）は、今と変わらない

### 型

```ts
export type SongPerformance = {
  /** ABC 記法のサブセット。メロディ・コード・歌詞の音節を持つ。 */
  abc: string;
  defaultBpm: number;
  strum: "down" | "d-du-udu";
  /** 再生で原譜と変えた点（フェルマータを伸ばさない等）。 */
  note?: string;
};
// Song に performance?: SongPerformance を足す
```

### テストで固定すること

1. **小節の長さ**が拍子と合う。最初の小節（弱起）と最後の小節だけは短くてよい
2. **コードの並び**が、歌詞コード譜のコードの並びと一致する（同じコードの続きも含む）
3. **歌詞とコードの位置**が歌詞コード譜と一致する。`w:` の音節を連結した文字列と、歌詞コード譜からコードを外した文字列が、空白を除いて NFC で一致すること（ʻ や長音符号も含む）。そのうえで、k 番目のコード記号の文字位置が、その時刻に鳴っている音節の先頭か、次に歌い出す音節の先頭に等しいこと。休符中は「次」だけを許す。タイとメリスマは、最初の音節を「鳴っている音節」とする
4. 使うコードの集合が `song.chords` と一致する
5. 歌詞コード譜を持つ曲は `performance` も持つ（全曲の転記が終わってから有効にする）
6. メロディの音域が G3〜C6 に収まる（オクターブの書き間違いを拾う。Nā Lei o Hawaiʻi を C へ移すと G3 まで下がるため、下限を G3 にする）
7. **小節ごとのコード**が外部の表と一致する。聖者の行進は `progression`（Lesson 08 の表）と、1923年版の5曲は各曲ファイルのコメントにある小節表（簡略化後）と比べる。テスト 2・3 は譜面を基準にしているので、譜面と ABC を同時に間違えると通ってしまう。それを別の基準で止める

3 と 7 がこの設計の要になる。記法を変えずに別データを持つと、譜面と再生が食い違っても気づけない。そのずれをビルドで落とす。

### 手で確かめること

- 着手前に、タイ・休符・メリスマを含む1小節を abcjs に描かせ、`w:` の割り当てを確かめた。休符は飛ばし、タイの続きの音符には音節を1つ割り当てる。サブセットの規則をこれに合わせた
- 曲ごとに、転記した ABC を abcjs で五線譜に描き、原譜の切り抜きと並べて見比べる（scratchpad、Playwright でスクリーンショット）
- 二重唱の箇所は上の声部を旋律とする
- 実ブラウザで再生し、光るコードが進むこと、コンソールにエラーが出ないこと、幅 320px で崩れないことを確かめる
- **音が正しく聞こえるかは、こちらでは確かめられない。** 未検証として引き渡し、ユーザーに聴いてもらう

### 転記の途中で見つかったずれ（聖者の行進）

Lesson 08 の進行表と歌詞コード譜が食い違っている。旋律に当てると次のとおり。

- 表は11小節目から F。11小節目の頭の音節は「be」だが、譜面は「in」に F を置いている（半小節遅い）
- 表は14小節目が G7。14小節目の頭の音節は「saints」だが、譜面は「go」に G7 を置いている（半小節遅い）

小節の区切りは、「Oh when the」を1小節目の2〜4拍目に置く読み（1行＝4小節、16小節で1周）で数えた。Carnegie Hall の譜面がこの区切りで、CC0 の MIDI も音の時刻がこの区切りに合う（11小節目の頭が「be」、14小節目の頭が「saints」）。「Oh when the」を1小節目より前の弱起とする区切りでは、譜面の全コードが表より半小節〜1小節早くなり、表との食い違いはかえって増える。

Lesson 08 の譜面の説明は「上の表と同じ進行を、コードが替わる場所だけで書いています」なので、**表に合わせて譜面を直す**。本文の「『go』を歌い出すところではもう G7 が鳴っている状態にします」も「saints」に直す。

## ステップ

各ステップの完了確認は `npm run lint`・`npm test`・`npm run build`。コミットと公開は deploy スキルの手順で行う。

## 悪魔の代弁者

- **半年後に破綻するとしたら、転記ミス。** 耳で確かめられない。小節の長さ・コードの並び・コードの位置の3つをテストで固定し、五線譜に描いて原譜と見比べる。それでも音高の読み違いは残りうる。未検証として引き渡す
- **一番複雑なのは、コードの位置と音節の突き合わせ（テスト 3）。** 省けばパーサの `w:` 処理も要らない。しかし省くと、今回の聖者の行進のずれのように、譜面と再生の食い違いに気づけない。残す
- **ストロークの切り替えは要るか。** 依頼は「正解を聞く」だけで、要らない。当初は Lesson 11・14 の2段階（ダウンだけ → D-DU-UDU）に合わせて入れる案だった。しかし幅 320px で操作が4つ積み重なると、最初の画面に譜面が見えなくなる。段階の練習は StrumPattern が担うので外す
- **作り込みすぎていないか。** カウントイン、繰り返し再生、再生位置の自動スクロール、操作の固定表示は入れない。実機で要ると分かってから足す
- **自作 ABC と本物の ABC の解釈がずれる。** 見比べに使う abcjs と解釈が違うと、見比べが当てにならない。サブセットを狭く保ち、臨時記号の持続とタイの扱いは ABC 2.1 の規則に合わせる

### 反映した指摘

1. **テスト 3 の定義があいまい** — 「譜面の塊が始まっていること」では、綴りの違う歌詞や別の版の歌詞が混ざっても通る。文字位置で定義し直し、歌詞の文字列そのものの一致も検査に入れた
2. **テスト 2・3 は譜面を基準にしている** — 譜面と ABC を同時に間違えると通る。小節ごとのコードを外部の表と比べるテスト 7 を足した
3. **光らせる単位** — 現行の `is-picked` は名前で一致を取るので、C が譜面のすべての C で同時に光る。位置で引く形にした
4. **終わりと裏タブ** — スケジューラに終わりが無い。onBeat は溜まった通知のうち最後の1つしか出さないため、終了の検知には使えない。裏タブからの復帰は小節の途中から再開する。対策として、最後の音の時刻で止め、タブが裏へ回ったときも止める
5. **弱起のストローク** — 短い小節にパターンをどう当てるかが未定だった。弱起ではストロークを鳴らさないと決めた
6. **abcjs と自作の `w:` の解釈差** — 見比べの前提が崩れる。着手前に1小節で確かめる手順を足した
7. **ストロークの切り替え** — 依頼の範囲外で、320px で譜面が押し下げられる。外した

### 反論して残した指摘

- **Lesson 08 の譜面修正は根拠不足**という指摘 — レビュアーは「Oh Lord I」を8小節目末の弱起に置く区切りなら現行の譜面が表と合うとした。区切りを MIDI の音の時刻で確かめるよう求められたので確かめた。CC0 の MIDI は「Oh when the」を小節の2〜4拍目に置いており、11小節目の頭が「be」、14小節目の頭が「saints」になる。Carnegie Hall の譜面も同じ区切り。レビュアーの区切りで数えると、譜面の全コードが表より早くなり食い違いが増える。修正は予定どおり行い、根拠を DDR に書く

### 見送った指摘

- **`playNotes` の波形をキャッシュする** — 1小節に最大6回、毎回 Karplus-Strong を合成する。StrumPattern が同じ負荷ですでに動いており、必須ではないとレビュアーも書いている。実機で重いと分かってから入れる
