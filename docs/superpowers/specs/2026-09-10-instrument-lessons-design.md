# instrument-lessons 設計仕様

作成日: 2026-09-10
対象: 楽器の独習教材サイト（第1弾: ウクレレ）

## 1. 目的と成功条件

**目的**: 楽器に触れたことのない人が、独習だけで「弾き語りで3曲を通して演奏できる」状態に到達するための教材を、Web サイトとして提供する。

**最初の利用者**: 本リポジトリのオーナー（ウクレレ所持済み、楽器経験なし、譜面は読めない前提）。

**成功条件**: 利用者が Lesson 01 から順に進み、課題曲3曲（聖者の行進 / Aloha ʻOe / Kaimana Hila）を、止まらずに歌いながら最後まで演奏できる。想定期間は 1日15分 × 約5週。

**成功条件ではないもの**: 譜面が読めるようになること、音楽理論の体系的理解、他人に教えられる水準。

## 2. 前提

- 利用者はウクレレを所持済み。機種は未確定のため、教材は標準的な **ソプラノ／コンサート、GCEA（High-G, re-entrant）** を前提に書く。Low-G の場合の差分は注記で補う。
- 五線譜は使わない。**コードダイアグラムと歌詞コード譜**のみで完結させる。
- 利用者は日本語話者。サイトの言語は日本語。
- 閲覧はスマートフォンと PC の両方。練習中はスマホを譜面台代わりに見る想定。

## 3. スコープ

### 作るもの

- ウクレレの全15レッスン（本文 + 図 + 練習ツール）
- 課題曲3曲の演奏用ページ（歌詞コード譜、コード図、テンポ可変の伴奏再生）
- 楽譜ライブラリ（PD ハワイアン曲を中心に15曲、進捗連動フィルタつき）
- 練習ツール7種（§8）
- 簡易な進捗記録（§10）
- 「人と合わせる」ステージの Coming Soon 枠（見出しと予定内容のみ、中身は空）
- 楽器を後から追加できる構造（§11）

### 作らないもの（意図的に除外）

| 除外するもの | 理由 |
|---|---|
| マイクによる音高検出チューナー | ウクレレ v1 には不要。ただし後付けできる構造にする（§9） |
| 進捗のエクスポート／クラウド同期 | localStorage で足りる。ブラウザ変更で消える旨を明記 |
| ユーザー登録・認証 | 単一利用者の静的サイト |
| 市販曲の歌詞・コード譜の掲載 | 著作権（§6） |
| 弦楽器共通キット（`src/kit/strings/`） | 楽器1つの段階で共有形を推測すると外す。ギター追加時に ukulele/ から引き上げる |
| 五線譜・TAB譜の表示 | 弾き語りの到達目標には不要 |

## 5. 楽器の抽象化

### 共通契約は薄くする

将来追加する楽器に**オタマトーン**（フレットなし・連続音程・コードの概念なし）が含まれるため、共通の楽器契約に弦・チューニング・コード形を持たせない。

```ts
// src/core/lesson/types.ts
export type Instrument = {
  id: string;          // "ukulele"
  slug: string;        // URL: /ukulele/
  name: string;        // "ウクレレ"
  tagline: string;
  curriculum: Curriculum;
};
```

コードダイアグラム、ストロークパターン、チューニングは**ウクレレモジュールの内部**に閉じる。

### ディレクトリ構成

```
src/
  core/
    lesson/        レッスン・カリキュラムの型、ルーティング、MDXレイアウト
    audio/
      output/      音の合成・再生・スケジューラ
      input/       （空。将来のマイク入力・音高検出用の置き場）
      pitch.ts     音名↔周波数（12平均律, A4=440）
    widgets/       Metronome, MelodyPlayer, TonePlayer
    progress/      進捗ストア
  instruments/
    registry.ts    楽器の登録
    ukulele/
      instrument.ts  メタ情報
      tuning.ts      GCEA
      chords.ts      コード定義
      curriculum.ts  レッスン一覧・課題曲
      widgets/       ChordDiagram, StrumPattern, ChordChangeTrainer, SongSheet
content/
  ukulele/
    lesson-01.mdx 〜 lesson-15.mdx
    songs/*.ts     課題曲データ
```

`core/audio/pitch.ts`・メトロノーム・メロディ再生は、オタマトーンでも確実に使うため最初から core に置く。それ以外の共有は、2つ目の楽器が来てから引き上げる。

### オタマトーン追加時に何が起きるかの検証

| 必要になるもの | 既存で足りるか |
|---|---|
| レッスン基盤・ルーティング・進捗 | ✅ core をそのまま使う |
| メトロノーム | ✅ core |
| 音名↔周波数、お手本メロディ再生 | ✅ core |
| 音高リボンの図 | ❌ `instruments/otamatone/widgets/` に新規追加 |
| マイクによる音程判定 | ❌ `core/audio/input/` に新規追加（構造は用意済み） |
| コードダイアグラム | 不要（ウクレレ側に閉じているので邪魔にならない） |

## 6. 練習曲・楽譜ライブラリと著作権

### 方針

1. 練習用フレーズは自作する
2. サイト内に掲載する曲は**日本と米国の両方で保護期間が満了した曲**に限る
3. 有名曲は曲名を挙げて外部コード譜サイトへリンクするに留め、歌詞・コード譜は転載しない

### 判定基準（二重基準）

サイトは GitHub Pages（米国ホスト）で公開するため、日本法だけの判定では足りない。次の両方を満たす曲だけを掲載する。

- **日本** — 作詞者・作曲者の**両方**が1967年12月31日までに死亡している（または伝承曲）
- **米国** — 初出版が1929年より前である

日本の保護期間は 2018-12-30 の TPP11 協定発効で「著作者の死後70年」へ延長されたが、施行日時点で消滅していた著作権は復活しない（保護の不遡及）。文化庁の Q&A により、1967年12月31日までに死亡した著作者の作品は満了済みで確定している。

米国側は、1929年より前に出版された作品が PD となる。日本で PD であっても米国の保護が残る例もあるため、この条件を別途課す。

### 除外した実例

判定を誤りやすい例を記録として残す。

| 曲 | 除外理由 |
|---|---|
| 夕焼小焼 | 作詞の中村雨紅が1972年没。2042年まで保護 |
| 椰子の実 | 作曲の大中寅二が1982年没。2052年まで保護 |
| 赤とんぼ | 日本では PD だが、1927年発表のため米国の保護が継続中 |

作曲者だけを見て判断すると事故る。**作詞・作曲の両方**を確認する。

### 課題曲

| 曲 | 作者 | 没年 | 判定 | 使用コード |
|---|---|---|---|---|
| When the Saints Go Marching In（聖者の行進） | 作者不詳（黒人霊歌、19世紀） | — | 伝承曲・PD | C, F, G7 |
| Aloha ʻOe | Queen Liliʻuokalani | 1917 | 1967年以前に没 → PD | C, C7, F, G7 |
| Kaimana Hila | Charles E. King（Andrew Cummings 補作）1916年発表 | King: 1950 | 1967年以前に没 → PD | C, C7, F, G7, D7 |

歌詞も同じ根拠で掲載可。

### 楽譜ライブラリ

`/ukulele/songs` に、掲載可能な曲を一覧するページを置く。ハワイアン曲を中心に構成する。

v1 の収録は15曲（課題曲3曲 + ハワイアン12曲）とする。候補は Live Ukulele の PD リストに100曲以上あり、うち出版年の判明したものが約55曲（すべて1929年より前）。ただし同リストは作者自身が未検証と明記しているため、候補の入口としてのみ使い、掲載する曲は個別に裏取りする。

収録候補（実装時に個別検証し、初心者キーへ移調する）:

- Aloha ʻOe / Kaimana Hila / 聖者の行進（課題曲）
- On the Beach at Waikiki (1915) / Hawaiʻi Ponoʻī (1874) / Kāua i ka Huahuaʻi (1860)
- Sanoe (1870s) / Kuʻu Pua i Paoakalani (1895) / Queen's Prayer (1895)
- Ke Kali Nei Au (1925) / Nā Lei o Hawaiʻi (1915) / Pālolo (1917)
- Pūpū a ʻo ʻEwa (1870s) / Hilo Hanakahi (伝承) / Papalina Lahilahi (伝承)

Ke Kali Nei Au は King によるハワイ語詞のみを掲載する。1958年の英語詞（Hoffman / Manning）は保護期間中のため扱わない。

#### 一覧ページの絞り込み

- **今の自分が弾ける曲** — 進捗記録の習得済みコードだけで弾ける曲に絞る
- コード数（3コード / 4コード / 5コード以上）
- セーハを含むかどうか

#### 権利情報のビルド時強制

曲データに検証記録を必須フィールドとして持たせる。

```ts
export type SongLicensing = {
  lyricist: { name: string; died: number | "traditional" };
  composer: { name: string; died: number | "traditional" };
  firstPublished: number;
  verifiedOn: string;    // "YYYY-MM-DD"
  sources: string[];     // 出典URL、1件以上
};
```

テストで次を検査し、満たさない曲があればビルドを落とす。

- `firstPublished` が 1929 未満
- 作詞者・作曲者の没年がいずれも 1967 以下、または `"traditional"`
- `sources` が1件以上ある

同じ記録を `docs/songs-licensing.md` にも人が読める形で残す。曲を追加するときは同ファイルへの追記を必須とする。

### 却下した案

- **Astro + islands** — コンテンツサイトとしては理論上最適だが、既存3プロジェクトと別スタックになるコストが確実に発生する一方、15〜30本規模のレッスンでは静的出力の体感差が出にくい。
- **素の HTML/CSS/JS** — レッスンが増えると共通レイアウトの手作業複製が破綻し、楽器の抽象化ができない。

## 9. 音声エンジン

### 合成方式

**Karplus-Strong 法**で撥弦音を合成する。オシレータの単純な正弦波・矩形波では弦楽器に聞こえず、教材として音程確認以上の役に立たないため。

実装は `OfflineAudioContext` ではなく、Float32Array へ直接生成して `AudioBuffer` に載せ、`AudioBufferSourceNode` で再生する。AudioWorklet より単純で、ブラウザ差の影響も受けにくい。

```
1. 長さ N = round(sampleRate / frequency) のノイズバーストを用意
2. y[n] = damping * 0.5 * (y[n-N] + y[n-N-1]) を繰り返して減衰させる
3. 音量エンベロープを掛けて AudioBuffer 化
```

### 音名↔周波数

12平均律、A4 = 440 Hz 基準。`core/audio/pitch.ts` に置く。

ウクレレ標準チューニング（High-G）の基準周波数:

| 弦 | 音名 | 周波数 |
|---|---|---|
| 4弦 | G4 | 392.00 Hz |
| 3弦 | C4 | 261.63 Hz |
| 2弦 | E4 | 329.63 Hz |
| 1弦 | A4 | 440.00 Hz |

4弦が3弦より高い（re-entrant tuning）ことは Lesson 02 で明示的に説明する。初心者が最も混乱する点のため。

### 入力の分離

`core/audio/` を `output/`（合成・再生）と `input/`（マイク・解析）に分ける。v1 では `input/` は空だが、オタマトーンで必要となる音高検出をここへ足せる。

### ブラウザの制約

Web Audio はユーザー操作なしに開始できない。`AudioContext` は最初のタップ／クリック時に生成し、以降使い回す。この扱いを `core/audio/output/context.ts` に一箇所へ集約する。

## 10. 進捗記録

localStorage のみ。楽器ごとに独立。

```ts
// キー: "instrument-lessons:progress:v1"
type ProgressState = {
  [instrumentId: string]: {
    completedLessonIds: string[];
    lastLessonId: string | null;
    practiceDates: string[];   // "YYYY-MM-DD"
  };
};
```

- レッスン末尾に「完了にする」ボタン（取り消し可）
- コース一覧にチェックマークと進捗バー
- トップに「連続◯日練習中」

`practiceDates` は「完了にする」を押した日を記録する。連続日数はローカル日付で判定する（UTC ではなく `toLocaleDateString` 相当）。

localStorage が使えない環境（プライベートウィンドウ等）では例外を握りつぶし、進捗なしで正常に動作させる。ブラウザを変えると進捗が消える旨をトップに1行明記する。

## 12. テスト戦略

Vitest。**教材の破綻を機械検出することを最優先**とする。

| 対象 | テスト内容 |
|---|---|
| 権利情報 | 全曲に `licensing` があり、初出版が1929年より前、作詞・作曲の没年が1967以下または伝承曲、出典が1件以上あるか |
| カリキュラム整合 | 課題曲で使うコードが、その曲までのレッスンで導入済みのコードだけか |
| カリキュラム整合 | レッスンID の重複なし、day の連続性、参照先の MDX が存在するか |
| コード定義 | フレット番号が範囲内、指番号と押さえる弦の整合、弦数がチューニングと一致 |
| pitch.ts | 音名↔周波数の往復、A4=440、オクターブ境界、GCEA の実測値との一致 |
| ChordPro パーサ | コード位置の抽出、コードなしの行、記号のエスケープ |
| 進捗ストア | 完了の追加・取り消し、連続日数の日付境界、localStorage 不在時のフォールバック |
| ChordDiagram | 開放弦・ミュート・セーハの描画 |

音の実際の鳴りは自動テストしない（目視ならぬ耳視で確認する）。

## 13. デザイン方針

実装時に `frontend-design` スキルを呼んで視覚方針を決める。制約として:

- 練習中にスマホで見るため、**コードダイアグラムは腕を伸ばした距離で読める大きさ**を最優先する
- ハワイアンの空気感は配色でほのかに漂わせる程度とし、学習サイトとしての可読性を優先する
- 楽器が増えても破綻しないよう、楽器ごとのアクセントカラーをデータで持つ
